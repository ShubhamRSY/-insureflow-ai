## What the rule does

- A. Typed application line `Cooking operations:` whose whole body is none, no, nil, no cooking, no commercial cooking or no kitchen (full stop allowed). If the answer lacks it (P-059 finds it missing), `; Cooking operations: None` is appended as written, stored as a cited `also_quoted` part with offsets, row marked `rule_copied`, confidence not raised, review note kept ("cooking line copied from the application (P-075); no other document states cooking"). The copied line never makes a file read complete (D-133 answer 1). The words "no cooking" are never written by the rule.
- B. Runs when that none-line exists or the operations answer says none. Every document is scanned (other lines of the application too; the matched none-line and the insured's name are blanked, same length). Schedule files: the `cooking` column (header cell not read, header found in the first 5 lines so xlsx "sheet:" lines work); any value other than blank, no, none, n/a, na, 0, false is a hit. A hit opens a `cooking` conflict (side 1 the application line, or the operations answer; side 2 the hit with source, offsets, quote). Nothing is copied; operations keeps its value with NEEDS REVIEW "cooking: the documents disagree". Held like the P-070 count conflicts: `ready_to_route` false, open conflict listed, producer asked.
- C. `check_operations` also reads the application's `Cooking operations:` line when operations is cited from another document.
