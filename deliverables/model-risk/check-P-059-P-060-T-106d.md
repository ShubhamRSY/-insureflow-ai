Result: `PASS: 0 failure(s), 0 warning(s)`, exit 0. `dates_in` reads only ISO and M/D/YY. A text loss-run file with no parsed date gives no WARN, because the "cannot read" warning covers scans only. A gate built to stop T-104's post-run-date loss runs therefore passes the same defect when it comes in another format. This is the failure mode it exists to catch.
**Resolution (owner @senior-test-engineer; tooling only, no P-### needed):** (a) when a `loss-run*` file of any type yields no parsed date on a label or table line, report FAIL "no loss-run date read; check by eye". A scan that cannot be read also becomes FAIL, not WARN, so the exit code stops the freeze. (b) Parse month-name dates ("November 30, 2026", "30-Nov-2026", "Nov 30 2026"). (c) Add both cases to the self-check (textual post-run date → FAIL; no date → FAIL) and record them in `T-106d-lint.md`. @model-risk re-checks by re-running the probe above.
