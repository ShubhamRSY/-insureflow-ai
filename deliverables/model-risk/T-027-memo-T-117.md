## High findings

**H1 — Operations is below the floor on real omissions (owner @ai-engineer-assistant).**
- What happens: on 4 of the 20 files (248, 250, 254, 257), the stated application line "Cooking operations: None" is dropped from the operations answer.
- Why it is a model problem: on 251 and 255 the same model keeps "no cooking", so the behaviour is inconsistent, not a gold quirk.
- Effect: the misses are flagged for review, not silent, but operations automation is only 0.3.
- Remediation:
  - an approved P-### extractor change, so that operations always carries the stated cooking line, including "None";
  - or a recorded decision by @head-of-underwriting, made before the next gold exists, that "no cooking" is not a scored item for non-food classes.
  - Either way, the 3 M-class readings go to a new scorer version that is frozen before the next gold and never applied to T-117 (D-020): "to <customer>" is not a class, a faithful copied side remark is not an extra class, and "no … food service" means cooking=none.

**H2 — 0 of 3 planted document conflicts surfaced (owner @ai-engineer-assistant; @senior-underwriter for UI impact).**
- What happens: the model returned `conflicts: []` on all 20 files. The three planted disagreements were all missed:
  - SUB-249: square footage 2,800 vs 3,150;
  - SUB-252: suites 2 vs 3;
  - SUB-257: sales $412k vs "about 540k".
- Worst case, SUB-257: the GL rating base is shown as $412,000 with no conflict and no hold, status "complete — review pending". The scorer counts this sales value as a hit, and the 0.0 silent error rate does not see a conflict that was never raised.
- Context: this is not one of the fixed T-027 gate criteria. It is a production-use risk, and conflict hits were already weak on T-108 (10/20).
- Remediation:
  - a fix so that a disagreement between documents on a scored or rating field becomes an open conflict and a hold;
  - from the next hold-out on, **planted-conflict recall = 100%** is added to the T-027 gate. I am stating this now, before that gold exists, so it is pre-registered and not retroactive.

**H3 — The loss-run gate was not measurable because of a hold-out build error (owners @senior-underwriter for gold, @senior-test-engineer for the lint; process gap shared by @model-risk).**
- What happened: the T-117 builder passed the Carrier A/B "X to Y" term strings and `CL-` claim numbers into the Carrier C helper. The 4 dated Carrier C runs therefore do not match `simulation/carrier-loss-run-formats.md`:44, yet the gold calls them recognised.
- Who missed it: the gold-first lint, `--check-gold` and my own pre-run check (`T-117-check.md`, check 4, which compared dates only) all missed it.
- Remediation: a lint rule that runs every built carrier loss run through the frozen `carrier_run_check` and fails the build when the result disagrees with the gold "Expected loss run" line. My build check will add the same test.
