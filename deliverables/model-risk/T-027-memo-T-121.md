## High findings

**H1: P-077 Part B fails closed on ordinary single-location files: 4/20 false manual intake, 2 of them near-misses. This breaks every availability gate. (Owner @ai-engineer-assistant; decision @user.)**
- What happens: with a count of 1, Part B accepts the file only if the model's own `location_count.quote` passes an address-shape test (`STREET_WORDS` or `CITY_STATE_ZIP`). Two causes, both recomputed:
  1. **Highway-style addresses fail the shape test.** SUB-510 "1906 Hwy 290 W Ste 104, Brenham TX 77833" is rejected. My probes show that "1906 Highway 290 W, Brenham TX 77833" and "8800 US-59, Victoria TX 77904" are rejected too, while "12 FM 1960 Rd" passes only because of "Rd". Rural and highway-frontage premises are common in the Texas book.
  2. **The model quotes a reassurance sentence, not the premises line.** It used email text on 513 ("We lease one office suite on Marble Falls Ave"), 527 ("One address, one building.") and 529 ("Same single building."). All three applications have a valid `Premises address:` line. The near-miss wording that P-077 condition (c) says must stay in scope is exactly what draws the model to these quotes.
- Why it is High: it alone blocks the veto conditions. It also cuts automation from 0.861 (T-120) to 0.689. In production, about 1 in 5 clean single-location BOPs would go to full manual intake with "number of locations not clear", which an underwriter would learn to ignore.
- What would resolve it (all of these):
  1. A new P-### (`approve change P-###` typed by @user). It changes how the shape test is fed and must not loosen what reaches a person when there is any second-place signal. Proposed rule: with an integer count of 1, accept when **either** the count quote **or** the extracted, found-in-file `premises_address` quote shows one address. Also extend the shape test to highway forms (Hwy/Highway, US-, SH, FM, RR, CR, Loop, Spur, Route, with or without a suite), so Part A and Part B read the same address shapes. Everything else keeps failing closed: count > 1, null, not found, PO Box, a count word, and any Part A hit. Because this sends fewer files to a person than today, it is a loosening of Part B and is @user's call. Optionally, a prompt line asking that the count quote be the premises address line, with the PROMPT_VERSION change stated.
  2. Dev self-checks on new dev files, never 510/513/527/529. Positives (stay in scope): highway, FM and US-route premises; a count quote that is a reassurance sentence while the premises line is valid. Near-pass negatives (must still go to manual intake): a count of 1 with a second street in the email; a count of 1 whose only valid address is a mailing or PO Box line; "two stores"; a null count. Report dev false manual intake file by file before any gold.

**H2: Part A rule A3 (a different street address in another document, D-149) is bypassed by a role word anywhere on the same line. SUB-533 was detected by the model alone. (Owner @ai-engineer-assistant; decision @user.)**
- What happens (recomputed on a temp copy): the SUB-533 email is one paragraph on one line: "…keep stock and the delivery vans at our warehouse, 2215 Leonard Rd, Bryan, which is not on the app. **Carrier** A loss run attached." `ROLE_LINE` matches "Carrier", so the whole line is skipped. Separately, "Mailing address: same as premises" sits directly above the premises line, so `label_above` drops the premises address as well. Removing only the mailing line still leaves `detect` with no reason. The role-word skip alone is enough to miss the file.
- Why it is High: this is the exact shape that my T-120 H1 remediation step 1(c) and D-149 require a deterministic rule to catch. Producer emails routinely mention "carrier", "agent" or "loss run" in the same paragraph. Recall 6/6 rests on one model count (n = 1). The model counted 1 on all 20 in-scope files, so a single different reply on 533 would have been a leak. The gate is met, but the safeguard behind it is not the one the condition specified.
- What would resolve it:
  1. A P-### (stricter only). Scope the role exclusion to the sentence or clause that holds the address, not the whole line. Apply `label_above` only when the line above is a bare role label with no value of its own. "Mailing address: same as premises" must not hide the next line.
  2. Dev self-checks. Positives (go to manual): the SUB-533 shape on new files, with carrier, agent or insurance words elsewhere in the same paragraph, and a premises line under "Mailing address: same as premises". Near-pass negatives (stay in scope): an address in the same sentence as supplier, agent, carrier, mailing or prior; a carrier's or agency's office address in a signature. Request equality on dev in-scope files, and a count of files moving to manual intake under the new rule.
